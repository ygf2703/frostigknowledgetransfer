MCP: איך מחברים AI לכלים ולמידע

מה זה, איך זה בנוי, ואיך מתחילים לעבוד איתו - מהתאוריה ועד שרת ראשון משלכם
מאת: נעם פרוסטיג | 2 בנובמבר 2026
בקצרה: MCP (Model Context Protocol) הוא תקן פתוח שמגדיר איך אפליקציית AI מתחברת למערכות חיצוניות: קבצים, מסדי נתונים, כלי חיפוש ושירותים. במקום חיבור מיוחד לכל כלי ולכל מודל, כותבים שרת אחד שמדבר בתקן, וכל אפליקציה שתומכת בתקן יכולה להשתמש בו.

חלק א: התאוריה

מה הבעיה ש-MCP פותר

מודל שפה, בפני עצמו, יודע לכתוב ולנתח, אבל הוא לא רואה את הקבצים שלכם, לא יודע מה יש ביומן ולא יכול לפתוח כרטיס במערכת הפניות. כדי לתת לו גישה, כל אפליקציה בנתה בעבר חיבורים משלה לכל שירות. התוצאה: עבודה כפולה, חיבורים שלא עוברים בין כלים, ובלגן של הרשאות.

MCP הוא שכבה משותפת. את החיבור כותבים פעם אחת, כשרת, והוא עובד מול Claude, Codex ועוד כלים שתומכים בתקן. אפשר לחשוב על זה כעל שקע אחיד: לא משנה איזה מכשיר מחברים, השקע זהה. (זו אנלוגיה להמחשה, לא ציטוט מהמפרט.)

שלושה שחקנים

שםמה זהדוגמה
Host (מארח)אפליקציית ה-AI שאתם עובדים איתהClaude Code, Claude Desktop, סביבת פיתוח עם AI
Client (לקוח)רכיב בתוך המארח שמחזיק חיבור אחד לשרת אחדהמארח יוצר לקוח נפרד לכל שרת
Server (שרת)תוכנה שחושפת יכולות: כלים, נתונים, תבניותשרת קבצים, שרת מסד נתונים, שרת של שירות כמו יומן

השרת יכול לרוץ אצלכם במחשב (תהליך מקומי) או להיות שירות מרוחק באינטרנט. התקשורת ביניהם היא הודעות JSON-RPC, והן עוברות באחת משתי דרכים: stdio לשרת מקומי, ו-Streamable HTTP לשרת מרוחק.

מה שרת יכול להציע: שלושה אבני בניין

אבן בנייןמה זהמי שולט
Tools - כליםפעולות שהמודל יכול להפעיל: חיפוש, יצירת אירוע, כתיבה למסד נתוניםהמודל מחליט מתי להפעיל, ואפשר לדרוש אישור מהמשתמש
Resources - משאביםמידע לקריאה בלבד: תוכן קובץ, סכמה של מסד נתונים, תיעודהאפליקציה
Prompts - תבניותתבניות הוראה מוכנות שהמשתמש בוחר, למשל "סכם את הפגישות שלי"המשתמש

ברוב השימוש היומיומי תפגשו בעיקר את הכלים. שימו לב להבדל בשליטה: כלי הוא משהו שהמודל מפעיל בעצמו, ולכן שם נמצאת רוב הסכנה, ושם כדאי להקפיד על אישורים.

מה השתנה בגרסה העדכנית

המפרט מתעדכן בגרסאות עם תאריך. הגרסה העדכנית היא 2026-07-28. השינויים המרכזיים לעומת 2025-11-25:

  • הפרוטוקול הפך ללא-מצב (stateless): אין יותר לחיצת יד פתיחה, וכל בקשה נושאת את גרסת הפרוטוקול והיכולות של הלקוח.
  • שרתים חייבים לתמוך בבקשת גילוי, server/discover, שמפרסמת גרסאות, יכולות וזהות.
  • שרת שצריך מידע נוסף מהמשתמש מחזיר בקשת קלט, והלקוח חוזר עם התשובה (Multi Round-Trip Requests).
  • הפיצ'רים Roots, Sampling, Logging סומנו כמיושנים, וגם התעבורה הישנה HTTP+SSE. מי שבונה עכשיו משתמש ב-Streamable HTTP.
מצב הגרסה: דף הגרסאות הרשמי קובע שהגרסה הנוכחית (Current) היא 2026-07-28, והבלוג הרשמי הכריז עליה כשחרור ב-28 ביולי 2026, יחד עם עדכון ארבעת ה-SDK המרכזיים. בדף רשימת השינויים נשארה בטעות המילה "draft", אבל זו לא טיוטה. https://modelcontextprotocol.io/docs/2026-07-28/learn/versioning | https://blog.modelcontextprotocol.io/posts/2026-07-28/
מה נבדק בפועל להכנת המדריך: ה-SDK של פייתון mcp 2.3.0, Claude Code 2.1.316 ו-Codex CLI 0.166.0 (רק רישום הגדרה). אפליקציית Claude Desktop לא נבדקה.
מה זה אומר לכם בפועל: אם אתם רק מחברים שרתים קיימים, כמעט אין שינוי בעבודה היומיומית. אם אתם בונים שרת, השתמשו ב-SDK עדכני והוא יטפל בפרטים האלה.

חלק ב: אבטחה והרשאות, לפני שמתחברים

חיבור AI לכלים נותן לו יד ארוכה. לכן לפני כל שרת שואלים שלוש שאלות: מי כתב אותו, לאילו נתונים הוא ניגש, ומה הוא יכול לשנות.

  • שרת מקומי רץ עם ההרשאות שלכם. שרת שמורידים ומריצים יכול לגשת למה שהמשתמש במחשב יכול. תריצו רק שרתים שאתם סומכים על המקור שלהם, או כאלה שכתבתם בעצמכם. המפרט מזהיר במפורש מפני שרתים מקומיים לא מהימנים.
  • תוכן חיצוני יכול להכיל הוראות זדוניות. שרת שמביא דפי אינטרנט, מיילים או מסמכים עלול להביא איתם טקסט שמנסה לתת פקודות למודל (prompt injection). לכן לא מחברים כלי שיכול לשלוח, למחוק או לשלם בלי אישור ידני.
  • מינימום הרשאות. התחילו בקריאה בלבד, ותנו הרשאת כתיבה רק כשצריך. אל תחברו את כל התיקיות במחשב כשמספיקה תיקייה אחת.
  • סודות לא נכתבים בשיחה ולא נשמרים בקבצים שמשתפים. מפתחות וטוקנים לא נדבקים בצ'אט, לא נכתבים בתוך פקודה (היא נשמרת בהיסטוריה של המסוף) ולא נשמרים בקובץ הגדרות שנכנס ל-Git. מעדיפים התחברות דרך OAuth, או הפניה למשתנה סביבה.
  • אישור לפני פעולה. השאירו את האפליקציה במצב שמבקש אישור על כלים שמשנים דברים.

אזהרת prompt injection בשרתים שמביאים תוכן חיצוני - https://code.claude.com/docs/en/mcp

Security Best Practices - https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices

חלק ג: מעשי, מחברים שרת אמיתי לתיקיית תרגול

נחבר שרת קיים ורשמי, שרת הקבצים של פרויקט MCP, ונתן לו גישה לתיקייה אחת בלבד. אין בו מפתחות וסיסמאות, ולכן זה תרגול בטוח להתחלה. דרישה: Node.js מותקן (בדקו עם node -v).

יוצרים תיקיית תרגול

mkdir ~/mcp-practice
echo "hello from file" > ~/mcp-practice/note.txt
נבדק על לינוקס. ב-Windows מתאימים את הנתיבים (לא נבדק).

מוסיפים את השרת ל-Claude Code

claude mcp add files -- npx -y @modelcontextprotocol/server-filesystem ~/mcp-practice

תוצאה צפויה: Added stdio MCP server files ... to local config. אחר כך:

claude mcp list

תוצאה צפויה: שורה files: ... - ✔ Connected.

נבדק עם Claude Code 2.1.316: ההוספה הצליחה והסטטוס היה Connected. מקור: https://code.claude.com/docs/en/mcp | חבילת השרת (גרסה 2.1.0): https://www.npmjs.com/package/@modelcontextprotocol/server-filesystem

או ב-Codex

codex mcp add files -- npx -y @modelcontextprotocol/server-filesystem ~/mcp-practice

הפקודה כותבת בלוק [mcp_servers.files] לקובץ ~/.codex/config.toml.

נבדק חלקית עם Codex CLI 0.166.0: ההגדרה נרשמה ב-config.toml. חיבור חי ושיחה לא נבדקו. מקור: https://developers.openai.com/codex/mcp

מנסים בשיחה

פותחים את הכלי ומבקשים: "מה יש בתיקיית התרגול? תקרא לי את note.txt". תוצאה צפויה: המודל יפעיל כלי כמו list_directory ו-read_text_file ויחזיר hello from file.

לא נבדק בשיחה עם מודל (לא היתה גישה למודל בבדיקה). נבדק ישירות מול השרת באמצעות ה-Inspector: הכלי read_text_file החזיר hello from file, וברשימת הכלים של השרת יש גם כלים כמו write_file ו-move_file.
שימו לב להרשאות: לשרת הקבצים יש גם כלים שכותבים, עורכים ומעבירים קבצים. לכן נותנים לו תיקיית תרגול ריקה מסודות ולא את תיקיית הבית, ומאשרים ידנית כל פעולת כתיבה.

שרת מרוחק וסודות: דוגמה סכמתית, לא נבדקה

שרתים מרוחקים של שירותים (יומן, מערכת פניות, וכדומה) מתחברים בכתובת שהספק נותן: 
# סכמתי: את הכתובת מקבלים מהספק של השירות
claude mcp add --transport http <name> <url-from-provider>
סודות: אל תכתבו מפתח בתוך הפקודה, כי שורות פקודה נשמרות בהיסטוריה של המסוף. העדיפו התחברות דרך OAuth (ב-Claude Code מתוך /mcp). אם חייבים מפתח, הגדרות Claude Code תומכות בהפניה ${VAR} למשתנה סביבה, כך שהמפתח עצמו לא נכתב בקובץ ההגדרות שנכנס ל-Git. מקור: https://code.claude.com/docs/en/mcp. שרת מרוחק ו-OAuth לא נבדקו.

חלק ד: מעשי, בונים שרת משלכם בעשר דקות

הדרך הכי טובה להבין MCP היא לבנות שרת קטן. נבנה שרת עם כלי אחד, משאב אחד ותבנית אחת. כל השלבים כאן הורצו בפועל עם Python 3.10 ו-mcp 2.3.0, חוץ ממה שמסומן אחרת.

מכינים פרויקט

mkdir hello-mcp
cd hello-mcp
python3 -m venv .venv
source .venv/bin/activate
pip install "mcp>=2"

ב-Windows מריצים .venv\Scripts\activate במקום source.

נבדק עם pip ו-Python 3.10 (הותקנה הגרסה mcp 2.3.0). המדריך הרשמי משתמש ב-uv במקום pip, ואותו לא נבדק. מקור: https://modelcontextprotocol.io/docs/develop/build-server

כותבים את השרת

יוצרים קובץ בשם hello_mcp.py:

from mcp.server import MCPServer

mcp = MCPServer("hello-mcp")

@mcp.tool()
def add_vat(amount: float, rate: float = 18.0) -> str:
    """Add VAT to an amount.

    Args:
        amount: Price before VAT
        rate: VAT rate in percent (default 18)
    """
    total = amount * (1 + rate / 100)
    return f"{amount:.2f} + {rate:g}% VAT = {total:.2f}"

@mcp.resource("notes://welcome")
def welcome() -> str:
    """A static note the AI app can read."""
    return "Welcome. This text comes from an MCP resource."

@mcp.prompt()
def summarize(text: str) -> str:
    """Prompt template: summarize a text in three bullets."""
    return f"Summarize the following in three short bullets:\n\n{text}"

if __name__ == "__main__":
    mcp.run(transport="stdio")

הכלי, המשאב והתבנית הם שלוש אבני הבניין מהחלק התאורטי. המודל קורא את התיאור ואת הטיפוסים כדי להבין מתי ואיך להפעיל את הכלי, ולכן תיאור ברור הוא חלק מהקוד. 18% הוא ערך ברירת מחדל לדוגמה בלבד.

נבדק: השרת הורץ מול לקוח ה-SDK, ו-add_vat(100) החזיר 100.00 + 18% VAT = 118.00. המשאב והתבנית נקראו בהצלחה.

בודקים עם ה-Inspector

לפני שמחברים ל-AI, בודקים שהשרת עובד (דורש Node 22.19 ומעלה). בתוך תיקיית הפרויקט, כשהסביבה פעילה:

npx @modelcontextprotocol/inspector --cli python hello_mcp.py --method tools/list
npx @modelcontextprotocol/inspector --cli python hello_mcp.py --method tools/call --tool-name add_vat --tool-arg amount=250

תוצאה צפויה: הפקודה הראשונה מציגה את הכלי add_vat עם הסכמה שלו, והשנייה מחזירה 250.00 + 18% VAT = 295.00.

נבדק במצב ה-CLI של ה-Inspector (עם Node 22). הממשק הגרפי (npx @modelcontextprotocol/inspector python hello_mcp.py) לא נבדק. מקור: https://modelcontextprotocol.io/docs/2026-07-28/tools/inspector

מחברים ל-Claude Code

claude mcp add hello-mcp -- /full/path/to/hello-mcp/.venv/bin/python /full/path/to/hello-mcp/hello_mcp.py
claude mcp list

תוצאה צפויה: hello-mcp: ... - ✔ Connected. שמים נתיב מלא לפייתון של הסביבה ולקובץ.

נבדק עם Claude Code 2.1.316: סטטוס Connected. מקור: https://code.claude.com/docs/en/mcp

מחברים ל-Claude Desktop (לא נבדק)

מוסיפים לקובץ claude_desktop_config.json תחת mcpServers ומפעילים מחדש את האפליקציה:

{
  "mcpServers": {
    "hello-mcp": {
      "command": "/full/path/to/hello-mcp/.venv/bin/python",
      "args": ["/full/path/to/hello-mcp/hello_mcp.py"]
    }
  }
}
לא נבדק: האפליקציה לא הותקנה בבדיקה. מבנה הקובץ לקוח מהמדריך הרשמי (שם הפקודה היא uv; כאן הוחלף בפייתון של הסביבה, כמו בצעד שנבדק ב-Claude Code). מקור: https://modelcontextprotocol.io/docs/develop/build-server

מנסים בשיחה

כותבים: "תוסיף מע"מ ל-250 שקל". תוצאה צפויה: האפליקציה תבקש אישור להפעיל את add_vat ותחזיר 250.00 + 18% VAT = 295.00.

לא נבדק בשיחה עם מודל. הכלי עצמו נבדק דרך ה-Inspector (שלב 3).
שגיאה נפוצה: בשרת stdio אסור להשתמש ב-print(). הוא כותב לאותו ערוץ שבו עוברות הודעות הפרוטוקול ושובר את החיבור. לרישום משתמשים ב-logging, שכותב ל-stderr. שגיאה נוספת: נתיב יחסי בהגדרות. השתמשו תמיד בנתיב מלא.

תרגילים להמשך

  • הוסיפו כלי שני, למשל המרת מטבע או חישוב מס, וכתבו לו תיאור ברור. בדקו אם המודל בוחר בו נכון.
  • הפכו את welcome למשאב שקורא קובץ טקסט מהמחשב שלכם, מתיקייה אחת בלבד.
  • נסו לבקש מהמודל משהו שהכלי לא אמור לעשות, ובדקו מה קורה. כך מבינים למה תיאור וטיפוסים מדויקים חשובים.
  • תרגיל אבטחה: הסתכלו ברשימת השרתים שהוספתם. לכל אחד, רשמו מה הוא יכול לקרוא ומה הוא יכול לשנות.

מתי כדאי MCP, ומתי לא

MCP מתאים כשאותו כלי או מקור מידע צריך לשרת כמה אפליקציות AI, או כשרוצים שהמודל יפעיל פעולות במערכת אמיתית בצורה מוגדרת ומבוקרת. למשימה חד-פעמית, סקריפט רגיל או העלאת קובץ לשיחה פשוטים יותר. וזכרו: חיבור נותן יכולת, ואחריות על מה שהיא עושה נשארת אצלכם.
